# Task template

Every groomed issue is rewritten into these four sections. Nothing else.

## Goal

One or two sentences. What the task achieves, in the user's terms, not the
implementation's.

## Acceptance criteria

A checklist of statements that are true when the task is done. Each one must be
**checkable** — someone should be able to run a command or look at the screen and
say yes or no, with no judgment call. Prefer concrete commands, inputs, and
expected output over adjectives.

Bad: "Search works well and handles typos."
Good: "`find "blu bottl"` returns Blue Bottle as the top result."

## Out of scope

What this task deliberately does not cover, especially anything a reader might
reasonably assume it includes. If something is moved out because it deserves its
own task, link the follow-up issue.

## Constraints

Which files may be touched, which libraries must or must not be used, and any
project rule that bears on this task. Points at `AGENTS.md` rather than restating
it, unless a rule is easy to violate here.
